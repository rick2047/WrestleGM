# Design: UI Testing Coverage + Snapshot Comment Enhancements

## Overview
Improve UI test organization to reflect the screen/module structure and ensure navigation coverage. Enhance the UI snapshot CI comment to show the latest snapshots in a collapsed table, while keeping errors visible when failures occur.

## Test Structure
- Split `tests/test_ui_flows.py` into focused modules by screen/flow area (e.g., `tests/ui_flows/test_main_menu.py`, `tests/ui_flows/test_booking.py`).
- Each module targets a specific screen and its navigation paths, aligned to `wrestlegm/ui/screens/*`.
- Ensure each screen is covered by at least one flow test.

## Snapshot Comment Rendering
- Add a UI-specific comment generator (separate from the core test comment) so core and UI snapshots remain distinct.
- The UI snapshot job should pass metadata (screen name + image path) to the UI comment script.
- Render the snapshot table inside a single `<details>` block; each image cell uses its own nested `<details>` so images are collapsed by default.
- On failure, include error details above the table (or replace the table if no snapshots exist).

## Source of Snapshot Images
Preferred order:
1. Use fresh snapshot artifacts generated by the UI snapshot job (always upload on success and failure).
2. Fall back to repository baselines if artifacts are missing.

## CI Integration
- Update only the `ui-snapshot-tests` job to generate/update the PR comment with snapshots.
- Keep the existing core-tests comment intact.

## Tradeoffs
- Uploading snapshots on success increases artifact size but guarantees latest images for comments.
- Splitting tests increases file count but improves ownership and coverage clarity.
